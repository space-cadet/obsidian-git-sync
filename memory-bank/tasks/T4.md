- [x] Changed files appear in a local Changes list.
- [x] A file can be staged and unstaged.
- [x] A message can be committed and the clean state is shown in an installed Obsidian host.

## Implementation Update

- The fixed Changes action bar now matches the reference action set: Select
  All, Pull, Push, and Fetch.
- Staging remains available through the section-level Stage selected and
  Unstage selected controls.
- Pull and Push use the same queued remote operation path as the Settings
  actions and record their request, progress, and result in Activity.
- Refresh, stage, and unstage updates now preserve the Changes shell, active
  control, and scroll position after mobile layout recalculation.
- Cmd/Ctrl-click, Shift-click, and mobile long-press dragging support
  multi-selection; section filters/sorts and file overflow actions are active.
- Successful local mutations reconcile known file state without a full vault
  scan. Full Changes scans are limited to initial/context refreshes and the
  explicit Refresh action; uncertain states expose a manual refresh prompt.
- The destructive remote actions are adjacent to Pull and Push in the Changes
  toolbar, with distinct muted-red styling and explicit confirmation modals.
- The original deleted-file report was reproduced: `git.add` in
  `isomorphic-git` fails when the worktree path is already missing. The
  deletion-aware `git.remove` path works in isolation, but the individual
  Changes staging flow was not changed in this session and remains a follow-up.

## Recent Evidence

- The user confirmed that the Changes toolbar Pull and Push actions work.
- The user confirmed the pushed Changes and progress-modal polish works.
- The user confirmed that the force-sync icons and colors render correctly on
  both desktop and mobile.
- Revert actions remain the only unimplemented Changes refinement; selection,
  filtering, sorting, overflow actions, and targeted refreshes are implemented.

## KISS Boundary

Start with direct file actions. Add selection or bulk-action machinery only if
the basic workflow demonstrates a need.
