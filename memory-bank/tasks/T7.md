## Implementation Update

- Added direct HTTP(S) Fetch, fast-forward-only Pull, Push, and Clone flows
  through `isomorphic-git` and the Obsidian `DataAdapter` filesystem bridge.
- Added Changes action-bar actions with clear completion or failure notices.
- Remote operations are serialized, recorded in Activity, and refresh the
  sidebar after successful completion.
- Remote progress reports setup, transfer, and finalization phases. Push no
  longer performs the old working-tree/history summary scan, and Pull/Clone
  expose an explicit Changes-needs-refresh state instead of scanning the vault.
- Clone refuses a non-empty vault-relative destination; Pull does not attempt
  conflict resolution in this KISS increment.
- Force Pull fetches the configured remote branch, resets the local branch ref,
  and checks out the remote tree. Force Push sends the selected branch with
  `force: true`; both actions require explicit confirmation.
- Normal Pull now uses explicit fetch, fast-forward-only merge, and checkout so
  mobile-compatible paths can be filtered without weakening desktop behavior.
- Mobile checkout skips paths containing unsupported filename characters and
  reports the exact skipped paths in the operation result. Desktop checkout
  retains the complete tree behavior.

Source implementation is complete for T7c/T7d/T7e/T7f. The user verified the
pushed remote workflow, including Pull and Push from the Changes toolbar,
desktop Force Push, and mobile Force Pull completion with one incompatible
path explicitly skipped. Fetch, Pull, Push, and Clone now have retained
progress/result feedback and phase-level Activity diagnostics. Additional
remote edge-case testing remains.

## Failure Evidence Update

- Pull now passes the configured commit author and committer because
  `isomorphic-git` requires an identity even for the fast-forward-only path.
- The Obsidian HTTP bridge now accepts the array-of-chunks request body used by
  Push, as well as async iterator bodies, and returns an async-iterable response.
- The user-provided Log evidence identified both failures: `MissingNameError`
  from Pull and `body.next is not a function` from Push.
- Nested `MultipleGitError` details now include the underlying error code,
  caller, and affected path where the Git library provides them. Adapter write,
  remove, mkdir, and rmdir failures also include their exact paths.
- The mobile failure was narrowed to `FILE_NOTCREATED` for a note containing
  `?` in its filename. The checkout now skips that unsupported path on mobile;
  the user confirmed Force Pull completed and reported the skip.

## Next Refinements

- Exercise non-fast-forward, divergence, authentication, empty-repository, and
  clone edge cases separately.
- Rename or remove remote files whose names cannot be represented by the
  mobile filesystem; the plugin can skip them, but cannot materialize them.

## KISS Boundary

Implement one direct authentication and transport path before adding
alternatives or automated recovery.
